# 申论评分

入口 `#/shenlun`；独立批改工作区 `#/shenlun/project/<id>` 不显示全站导航。当前只支持概括题，包含对策、原因、问题、作用、综合及自动判断。满分和字数以题目要求为准，可由用户校正，不按子类硬编码分值。

## 输入和识别

电脑和平板的录入区使用“题目与材料 / 我们的答案”子tab，一次显示一份满宽大编辑框；切换保留文本、原图及识别状态，缺少必填内容时自动切回对应页。手机继续上下排列。题目与材料支持最多12张图片，可排序、删除、预览；答案图片为单张。两处都支持相机、上传、拖入、图片粘贴或直接输入文字。单张上限12 MiB，题目图片合计40 MiB。PNG、JPEG、WebP直接送视觉模型，不预先缩小长材料的小字。

OCR采用一次性 Responses 请求：`store:false`，不使用会话或前一条响应。保留文字、行、段落、标点、序号，结果直接填入可编辑文本框。划改、疑似错字和无法辨认的地方单独作为视觉观察；不能将观察条目数当作完整错字或划改总数。模型、服务地址、方法版本、图序及图片SHA-256组成识别缓存身份。

答案视觉观察只在图片SHA-256和当前识别文字SHA-256都匹配时发送。换图、删图或编辑文字即失效；纯文本没有书写属性。识别期间用户编辑，旧回包不覆盖新文字，可主动采用识别结果。图片读取和识别未完成时禁止开始评分。

## 两阶段批改

1. 题目分析仅发送题目、材料和用户确认的要求，不包含答卷。依照六节笔记的方法形成参考答案、材料依据、教学配分要点和逐步解析。
2. 答案批改对照已确定的要点评价用户原文，输出每点得分、失分、表达评价和精确原句批注。AI配分明确标为参考，不能冒充官方标准。

普通结构化JSON足以描述批注，无需工具调用或执行模型生成的动作。模型文字只按文本呈现。客户端校验总分、逐点合计、依据、类型、引用与数值范围；每个参考评分点必须有可定位材料依据，每个实际给分点必须有可定位答卷依据。未定位的批注保留评价，不能在不相关的句子上强行着色。资料不足显示待核对，不显示正式零分。

`ShenlunCore.anchor` 用精确引文与出现次数定位UTF-16区间；重复引文没有位置时不猜第一处。共享标注阅读器处理重叠区间，支持答卷批注、材料编号、参考答案片段和双向定位。得分为绿色，需改进为红色，偏离为琥珀色，材料引用为蓝色，同时保留编号和文字提示。

## 项目和请求生命周期

独立 IndexedDB `summer-politics-shenlun-v1` 保存草稿、报告、原图Blob和OCR缓存。API Key只使用已有模型配置，不进入项目、报告或备份。项目可从历史重开；修改重评创建新草稿，原报告保留。

每次任务固定模型配置。提交只创建当前项目的请求；重复提交复用当前任务，浏览器支持时使用Web Locks避免多个标签重复调用。离开页面不取消已启动请求，回包只更新匹配项目及版本。刷新或关闭浏览器后，未完成任务标记中断，不自动重新付费调用；已完成的题目分析可继续使用。手动停止、超时、HTTP错误、断流、无效JSON和不合格结果均可手动重试。

草稿定时保存并在导航前刷新；只保存当前编辑会话的草稿，避免旧评分快照覆盖其他标签的新报告。跨标签读取会刷新数据库最新状态；存储失败时保留内存内容，并提示导出。

单项目导入导出与全站备份包含题目、答案、报告及相关观察，不包含原图或密钥。原图仅保留在创建项目的浏览器；导入后需要看原图时应重新上传。手机在原文和评价之间切换，电脑和平板保持左右对照。

## 方法与验证

方法依据 `assets/prompts/shenlun-methods.md`，系统提示实现于 `assets/js/shenlun-prompts.js`；来源为已核验的申论底层逻辑和五类概括题笔记。分析采用“我们先审题—粗读分层—精读找点—归纳合并—落笔”的教学说明，不要求输出私有内部推理。

相关测试：`tests/shenlun-core.cjs`、`tests/shenlun-prompts.cjs`、`tests/shenlun-integration.cjs`。本地模拟服务只验证界面和状态，不能代替用户实际模型的视觉识别与评分质量验证。
